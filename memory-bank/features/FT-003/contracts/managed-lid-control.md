# FT-003: Managed Lid Control Contract

## Role And Ownership

| Role | Value |
| --- | --- |
| Design Pack relation | `constituent` |
| Boundary | Persistent bidirectional XPC between GUI app and privileged daemon |
| Owns | `CTR-01..07` |
| Does not own | Feature scope, architecture selection, acceptance or execution sequence |
| Roles | app = desired-policy owner/audio consumer; daemon = lease/lid/deadline/sleep authority |

## Connector Semantics

| Concern | Contract |
| --- | --- |
| Connector kind and binding | Privileged Mach service from embedded Service Management daemon |
| Protocol / direction | Objective-C-compatible `NSXPCInterface`; app calls daemon, daemon calls app callback interface |
| Sync / async boundary | All operations use async replies/callbacks; daemon serializes policy state |
| Ordering / delivery | At-most-one close event per known transition; callback may be lost; ack is idempotent by event ID |
| Timeout / retry | App heartbeats while active; daemon owns lease and feedback deadlines; reconnect creates a new lease generation |
| Trust / security | Bilateral code-signing requirement binds exact bundle ID and Team ID in production |
| Failure / degradation | Any uncertain ownership revokes lease and restores native sleep; closed/pending sleep also requests system sleep |
| Compatibility | Exact `protocolVersion`; mismatch may answer health but must reject activation |
| Observability | Structured daemon log includes transition/event ID, policy, lease revoke reason and sleep result; no secrets |

## Contract Status And Compatibility

| Field | Value |
| --- | --- |
| Status | accepted |
| Version | `managed-lid-v2` |
| Compatibility | breaking relative to `m2-spike-v1/v2`; exact handshake required |
| Source authority | ADR-001 and FT-003 design |

## Operations / Messages

| ID | Operation / message | Direction | Semantics |
| --- | --- | --- | --- |
| `CTR-01` | `checkVersion(reply)` | app -> daemon | Returns protocol version and daemon euid; no lease side effect |
| `CTR-02` | `activate(policyRaw, reply)` | app -> daemon | For valid exact-version peer, replaces prior lease generation, sets `disablesleep=1`, returns accepted + effective policy |
| `CTR-03` | `heartbeat(reply)` | app -> daemon | Renews only current connection lease; rejected otherwise |
| `CTR-04` | `feedbackDidFinish(eventID, reply)` | app -> daemon | Accepts only current pending sleep event; duplicate/stale IDs return false without side effect |
| `CTR-05` | `lidDidClose(eventID, policyRaw)` | daemon -> app | Delivers one current transition outcome; event ID generated by daemon |
| `CTR-05a` | `sleepCancelled(eventID)` | daemon -> app | Cancels the current sleep warning when the lid reopens before acknowledgement |
| `CTR-06` | connection invalidation/interruption | bidirectional lifecycle | Revokes owned lease, restores native sleep and applies closed/pending fail-safe |
| `CTR-07` | lease/feedback deadline | daemon-local connector | Expiration enters the same fail-safe terminal action exactly once |

## Values And Validation

| Field | Type | Validation / semantics |
| --- | --- | --- |
| `policyRaw` | integer enum | `work=1`, `sleep=2`; any other value rejected, never defaulted |
| `eventID` | UUID string | daemon-generated; exact match to current pending event and lease generation |
| activation reply | `(accepted: Bool, effectivePolicyRaw: Int, message: String)` | false means app must show policy unknown/unmanaged |
| heartbeat/ack reply | `Bool` | true only when current lease/event accepted |

## State Mapping

| State | Meaning | App behavior |
| --- | --- | --- |
| `inactive` | no valid lease; native sleep enabled | show managed policy unavailable/unknown; reconnect when daemon ready |
| `active(work)` | live lease, wake inhibited | show work policy; play work sound on callback |
| `active(sleep)` | live lease, wake inhibited | show sleep policy; play sleep sound and ack completion |
| `pendingSleep(eventID)` | sleep callback sent, deadline running | complete/ack exact event; do not change meaning of prior callback |
| `sleeping/failSafe` | native sleep restored; explicit sleep may be requested | reconnect/reactivate only after wake |

## Errors And Failure Semantics

| Condition | Retryable | Required behavior |
| --- | --- | --- |
| protocol/signing mismatch | no until matching build | reject lease; native sleep remains enabled |
| invalid policy/event ID | no for same request | reject without mutation |
| heartbeat expired | yes via new connection after safe reset | revoke and fail safe |
| feedback deadline expired | no for old event | sleep; late ack ignored |
| connection lost | yes via new connection after safe reset | revoke and fail safe |
| `pmset`/sleep adapter failure | not automatically in same event | log; never report managed success; preserve/restore safest attainable native state |

## Idempotency And Ordering

- Activation creates a new generation and invalidates pending IDs from the old
  generation.
- Repeated known `closed` observations do not create new IDs.
- A valid sleep acknowledgement cancels its deadline and can trigger sleep only
  once.
- Deadline and acknowledgement may race; daemon serialization selects one
  terminal transition and ignores the loser.
- No automatic retry may re-enable `disablesleep` after lease revocation.
- Opening the lid during `pendingSleep` cancels the deadline and invalidates the
  event; a later close receives a new event ID.

## Security And Sensitive Data

- Daemon accepts only peers satisfying exact app signing requirement; app
  requires exact daemon identity. Team-ID-less ad-hoc matching is development
  evidence only and is not production-safe.
- No XPC method accepts executable paths, arguments, shell text or arbitrary
  preference keys.
- Logs contain generated event IDs and reason codes only; no credentials or
  personal data.
